# Визуализатор графа зависимостей пакетов (вариант 6)

## Общее описание

Консольное приложение на Python для анализа и визуализации графа
зависимостей пакетов Python (pip). Менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются: только
стандартная библиотека Python.

Все настройки задаются в конфигурационном файле формата CSV. При
запуске программа читает и проверяет конфигурацию и строит граф
зависимостей заданного пакета с учётом транзитивности (зависимости
зависимостей) по данным репозитория пакетов (например, PyPI) или
тестового репозитория из файла. Граф выводится списком, описывается
на языке диаграмм D2, показывается картинкой и, если задан параметр
`ascii_tree`, выводится в виде ASCII-дерева. У каждого пакета
указана версия: для реальных пакетов — актуальная (последняя на PyPI),
для тестового репозитория — из файла.

Структура проекта:

| Путь | Что там |
|---|---|
| `src/main.py` | точка входа, аргументы командной строки |
| `src/config.py` | чтение и проверка конфигурационного файла CSV |
| `src/repository.py` | получение описания пакета из репозитория |
| `src/requirements.py` | разбор строк зависимостей (PEP 508) |
| `src/graph.py` | построение графа обходом в глубину без рекурсии |
| `src/file_repository.py` | тестовый репозиторий из текстового файла |
| `src/diagram.py` | описание графа на D2, изображение и его показ |
| `src/ascii_tree.py` | вывод зависимостей в виде ASCII-дерева |
| `config.csv` | пример конфигурации |
| `tests/` | модульные тесты, примеры конфигураций, демонстрация |

## Функции и настройки

### Запуск

```sh
./run.sh [--no-show] [путь_к_конфигурации.csv]
```

Без пути используется `config.csv` из текущей папки. С `--no-show`
изображение графа сохраняется, но не открывается (удобно, когда
программа запускается много раз подряд, как в скриптах демонстрации).

### Формат конфигурационного файла

Первая строка — заголовок `parameter,value`, далее по одному параметру
на строку. Все параметры обязательны.

```csv
parameter,value
package_name,requests
repository,https://pypi.org/pypi
test_repo_mode,false
ascii_tree,false
```

| Параметр | Описание |
|---|---|
| `package_name` | имя анализируемого пакета |
| `repository` | URL-адрес репозитория или путь к файлу тестового репозитория |
| `test_repo_mode` | режим работы с тестовым репозиторием |
| `ascii_tree` | режим вывода зависимостей в формате ASCII-дерева |

Допустимые значения:

- `package_name` — имя пакета Python по PEP 508: латинские буквы,
  цифры, `.`, `_`, `-`; начинается и заканчивается буквой или цифрой.
- `repository` — URL со схемой `http` или `https`, например
  `https://pypi.org/pypi`. В режиме тестового репозитория — путь
  к существующему файлу; относительный путь считается от папки,
  где лежит файл конфигурации.
- `test_repo_mode`, `ascii_tree` — `true` или `false` (также `yes`/`no`,
  `1`/`0`, регистр не важен).

### Получение зависимостей

Используется формат пакетов Python (pip). Описание пакета берётся
через JSON API репозитория: по адресу `<repository>/<пакет>/json`,
для PyPI это `https://pypi.org/pypi/requests/json`. Из ответа
берётся поле `requires_dist` — список зависимостей последней версии
пакета в формате PEP 508, например `idna<4,>=2.5`.

Строки зависимостей разбираются вручную (`src/requirements.py`),
pip и сторонние библиотеки не используются. В граф входят
обязательные зависимости: строки с маркером `extra == "…"` нужны
только для дополнительных возможностей пакета и пропускаются.
Зависимости с маркерами окружения (например,
`sys_platform == "win32"`) входят в граф независимо от текущей
системы. Имена пакетов приводятся к единому виду по PEP 503
(`charset_normalizer` → `charset-normalizer`).

### Построение графа

Граф строится обходом в глубину (DFS) без рекурсии: вместо
рекурсивных вызовов используется явный стек. Каждый пакет кладётся
в стек при входе (запрашиваются и добавляются в стек его
зависимости) и при выходе (пакет обработан). Поэтому всегда известен
путь от корня до текущего пакета.

- Каждый пакет запрашивается из репозитория один раз, общие
  зависимости не дублируются.
- Если при обходе встречается пакет, который ещё лежит на текущем
  пути, найден цикл (например, `A -> B -> C -> A`). Цикл
  запоминается и выводится, обход продолжается без зацикливания.
- Если зависимости какого-то пакета получить не удалось (например,
  его нет в репозитории), он остаётся в графе без зависимостей,
  а причина выводится отдельно. Ошибка для самого анализируемого
  пакета завершает программу с кодом 1.

### Режим тестового репозитория

При `test_repo_mode = true` параметр `repository` — путь к файлу
с описанием графа. Пакеты называются большими латинскими буквами,
каждая строка описывает пакет, его версию и прямые зависимости:

```
A 2.1.0: B C
B 1.4: D
C 3.0.2: D
D 0.9:
```

Версия (числа через точку) необязательна: строка `A: B C` тоже
допустима, тогда пакет показывается без версии. Пустые строки
пропускаются. Ошибки файла: строка без двоеточия, имя не из больших
латинских букв, неверная версия, пакет описан повторно. Зависимость,
которая не описана в файле, считается не найденной в репозитории.

Готовые тестовые репозитории в `tests/repos/`:

| Файл | Случай |
|---|---|
| `single.txt` | один пакет без зависимостей |
| `chain.txt` | цепочка A → B → C → D (без версий) |
| `simple.txt` | «ромб»: B и C зависят от общего D |
| `cycle.txt` | цикл A → B → C → A |
| `self_cycle.txt` | пакет зависит сам от себя |
| `complex.txt` | 8 пакетов, общие зависимости и три цикла |
| `missing.txt` | зависимость X не описана в файле |
| `bad_format.txt`, `bad_name.txt`, `bad_version.txt`, `duplicate.txt` | ошибки в файле |

### Визуализация

После построения графа программа:

1. Выводит граф списком «пакет версия -> зависимости» и найденные
   циклы.
2. Формирует текстовое представление графа на языке диаграмм D2 и
   сохраняет его в `output/<пакет>.d2`. Узлы подписаны именем и
   версией, анализируемый пакет выделен цветом, пакеты, которые не
   удалось получить, — красным пунктиром.
3. Делает из него изображение `output/<пакет>.svg` программой `d2`
   и показывает его в браузере по умолчанию: рядом создаётся страница
   `output/<пакет>.html` с изображением, и открывается она. Сам файл
   `.svg` система может отдать графическому редактору (например,
   Illustrator), который не распознаёт шрифты, встроенные d2.
4. Если `ascii_tree = true`, выводит зависимости в виде ASCII-дерева.
   Дерево обходится в глубину без рекурсии. Общая зависимость
   показывается под каждым пакетом, которому она нужна; пакет, уже
   стоящий на пути от корня, отмечается «(цикл)», и обход дальше не
   идёт.

Для изображения нужна программа d2 (не библиотека для получения
зависимостей, а средство рисования диаграмм):

```sh
brew install d2        # macOS
```

Другие способы установки: <https://d2lang.com/tour/install>. Если d2
не установлена, текст на D2 и ASCII-дерево всё равно выводятся,
программа сообщает об ошибке визуализации и завершается с кодом 1.

Пример `output/A.d2` для `tests/repos/simple.txt`:

```
direction: down

"A": "A 2.1.0"
"A".style.fill: "#cfe8ff"
"A".style.bold: true
"B": "B 1.4"
"D": "D 0.9"
"C": "C 3.0.2"

"A" -> "B"
"A" -> "C"
"B" -> "D"
"C" -> "D"
```

### Сравнение со штатными инструментами

У pip нет собственной команды для вывода дерева зависимостей
(`pip show` показывает только прямые зависимости установленного
пакета), поэтому для сравнения взят стандартный инструмент
`pipdeptree`. Скрипт `tests/compare_with_pipdeptree.sh` выводит
ASCII-дерево программы и вывод `pipdeptree` для тех же пакетов.
pip и pipdeptree нужны только этому скрипту: они ставятся во временное
виртуальное окружение, которое затем удаляется.

Результаты на 6 ноября 2026 года (Python 3.13):

```
программа                         pipdeptree
flask 3.1.3                       Flask==3.1.3
├── blinker 1.9.0                 ├── blinker [required: >=1.9.0, installed: 1.9.0]
├── click 8.5.0                   ├── click [required: >=8.1.3, installed: 8.5.0]
├── importlib-metadata 10.1.0     ├── itsdangerous [required: >=2.2.0, ...]
│   └── zipp 4.1.2                ├── Jinja2 [required: >=3.1.2, installed: 3.1.6]
├── itsdangerous 2.2.0            │   └── MarkupSafe [required: >=2.0, ...]
├── jinja2 3.1.6                  ├── MarkupSafe [required: >=2.1.1, ...]
│   └── markupsafe 3.0.4          └── Werkzeug [required: >=3.1.0, ...]
├── markupsafe 3.0.4                  └── MarkupSafe [required: >=2.1.1, ...]
└── werkzeug 3.1.9
    └── markupsafe 3.0.4
```

Структура деревьев совпадает (те же связи и те же версии), отличия:

1. **Маркеры окружения.** pipdeptree показывает только то, что pip
   установил на этой системе. `importlib-metadata` и `zipp` нужны
   `flask` только на Python < 3.10, а `tzdata` нужна `pandas` только
   на Windows, поэтому в pipdeptree их нет. Программа включает все
   обязательные зависимости независимо от системы.
2. **Версии.** Программа показывает актуальную (последнюю) версию
   каждого пакета на PyPI, pipdeptree — установленную версию и
   требование к ней (`required: >=2.0`). При свежей установке они
   совпадают, в старом окружении могут отличаться.
3. **Порядок.** pipdeptree сортирует зависимости по алфавиту,
   программа выводит их в порядке, указанном в описании пакета.
4. **Имена.** pipdeptree пишет имя, как его указал автор (`Flask`,
   `Jinja2`), программа приводит имена к единому виду по PEP 503.
5. **Источник данных.** pipdeptree читает уже установленные пакеты,
   программа получает данные из репозитория без установки.

### Обработка ошибок

При ошибке программа выводит список всех найденных проблем и
завершается с кодом 1. В конфигурации проверяются:

- файл: не существует, пустой, не читается;
- структура: неверный заголовок, строка не из двух столбцов;
- параметры: неизвестный, указан повторно, не задан;
- `package_name`: пустое или недопустимое имя;
- `repository`: пустое значение, неверный URL, нет файла тестового
  репозитория;
- `test_repo_mode`, `ascii_tree`: значение не `true`/`false`.

При визуализации: программа d2 не установлена или завершилась с
ошибкой, не удалось открыть изображение.

При обращении к репозиторию: пакет не найден, сервер недоступен,
ошибка сервера, ответ не в формате JSON или без нужных полей; для
тестового репозитория — ошибки в файле и неизвестный пакет.

## Сборка и запуск тестов

Сборка не нужна, требуется Python 3.8+ без дополнительных пакетов.

```sh
./run.sh                    # запуск с config.csv
./tests/run_tests.sh        # модульные тесты (без обращения к сети)
./tests/demo_errors.sh      # демонстрация верных и ошибочных конфигураций
./tests/demo_dependencies.sh  # графы реальных пакетов из PyPI
./tests/demo_test_repo.sh   # графы на тестовых репозиториях
./tests/demo_visualization.sh # D2, изображения и ASCII-деревья 3 пакетов
./tests/compare_with_pipdeptree.sh # сравнение с pipdeptree (нужен pip)
```

Примеры конфигураций лежат в `tests/configs/`: `valid_*.csv` — верные,
`pypi_*.csv` — разные пакеты и ошибки репозитория, `viz_*.csv` —
пакеты для визуализации (с ASCII-деревом), `graph_*.csv` —
тестовые репозитории из `tests/repos/`, остальные
демонстрируют по одному виду ошибок конфигурации, `many_errors.csv` —
несколько ошибок сразу.
